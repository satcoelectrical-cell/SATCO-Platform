## Registered capability boundary

PATCH-049 provides deterministic, explainable, evidence-linked and
non-authoritative Project completeness and missing-information intelligence.
For one freshly authorized Project/Workspace context it identifies what is
present, safely missing, indeterminate or not disclosed, then derives bounded
clarification questions and checklist items from a static version-controlled
rule catalog.

The capability consumes PATCH-048 typed Project Context and, only where an
explicit rule requires it, bounded authorized one-hop EKG projections. It owns
no source fact, Project standing, engineering decision, aggregate, workflow,
task, database table or model-backed AI answer. Results are ephemeral
observations for Human review, not approval or engineering truth.

## Authority and safety boundary

- Trusted actor and server-derived Organization/Project/Workspace scope are
  authorized before any analysis or disclosure.
- Protected, unavailable or truncated information is never converted into a
  missing assertion.
- Every disclosed finding identifies its stable rule/version, applicability
  basis, classification, visible evidence, observation interval, limitations
  and truncation state.
- Humans act only through the existing canonical owning capabilities. PATCH-049
  performs no mutation and creates no task or accepted knowledge.
- No overall completeness score or percentage is produced because V1 has no
  truthful universal denominator.

## Explicit exclusions

Excluded are engineering solution or material recommendations, preliminary
BOM direction, Project-health scoring, model-backed AI, provider routing, RAG,
embeddings, semantic/vector search, generic chat, autonomous engineering or
workflow, task creation, procurement, licensing/anti-copy, graph persistence,
multi-hop traversal, customer-configurable rule builders, saved assessment
history, source mutation and all PATCH-050 capability.
