# ADR-005

Status: Accepted

Title:
JWT Protected API Endpoints

Date:
2026-07-25

---

## Context

SATCO Platform requires authenticated access to backend resources.

API endpoints must not be publicly accessible without user identity validation.

---

## Decision

All protected API endpoints use JWT-based authentication.

Authentication validation is implemented through FastAPI dependencies.

The authentication flow is:

Client
↓
JWT Access Token
↓
OAuth2 Dependency
↓
get_current_user()
↓
User Validation
↓
Protected Endpoint

---

## Implementation Rules

- Access Token is used for API authorization.
- Refresh Token is used for session renewal.
- Passwords are never stored in raw form.
- Authentication logic remains separated from API routers.
- Business logic remains inside Services.
- Database access remains inside Repositories.

---

## Protected Modules

Current protected API modules:

- Projects
- Customers
- Contacts

---

## Future Extension

This architecture provides the foundation for:

- Role-Based Access Control (RBAC)
- Permission management
- User administration
- Audit logging

---

## Consequences

All future protected endpoints must use the authentication dependency layer.

Authentication decisions must not be implemented directly inside routers.
