# EDS-040 — Governed Organizational Memory Admission & Reuse Experience

Status: ACCEPTED. Architecture/QG-M1: PASS.

## Product semantics

Only an authorized exact Human-accepted Technical Report may be presented for admission. The accepted detail displays purpose, immutable content, qualification, accepted aggregate version, Project/Workspace context, and canonical provenance already returned by the Technical Report service. Admission is a separate explicit form requiring Human admission rationale, Human authority rationale, deliberate confirmation, and optional bounded reuse restrictions. The browser never authors source identity, provenance, Organization, standing, digest, or accepted version; it forwards fields from the currently authorized accepted response and the Memory service independently reauthorizes all authority before mutation.

Audience is the accepted empty V1 audience. PATCH-040 creates no named-Human audience UX or policy. Acceptance, navigation, repeated use, and AI output never admit Memory.

Active Memory discovery uses real Project and Workspace selectors backed by authorized APIs. Lists remain bounded by PATCH-034 ordering/count/continuation rules. Exact detail uses `get_active` with provenance and `reuse_intent`; the service reauthorizes current source, scope, audience, and provenance before disclosure. Protected, revoked, withdrawn, superseded, foreign, or unavailable records disclose no identity, count, rationale, lineage, provenance, or denial reason.

Human consultation displays active standing, admitted content, exact source Report link, source version, qualification/limitations, admission rationale, restrictions, attribution, and safe provenance inseparably. Consultation creates no new engineering authority or canonical relationship.

Report and Command Center continuation may deep-link only to authorized exact Memory detail. Loading, truthful empty, protected, invalid, conflict, unavailable, and success states remain distinct without protected detail. All UI is keyboard operable, labeled, non-color-only, responsive, and uses only API state.

No backend schema, Aggregate, migration, lifecycle, AI, Evidence, search, or cross-Organization capability is introduced.
