## 5. Canonical Terminology

The implementation shall use these exact labels:

```text
Manifesto Alignment Record
Manifesto Compliance: PASS | FAIL
Manifesto Alignment Verified: YES | NO
QG-M1 — Manifesto Alignment
QG-M1 Readiness Result: PENDING | PASS | FAIL
QG-M1 Final Result: PENDING | PASS | FAIL
```

`PENDING` is allowed for QG-M1 results but not for AR Manifesto Compliance.
An incomplete AR must remain under review rather than emit conditional PASS.

## 6. Cross-Document Invariants

- all principles are binding; only direct effect may differ.

## 7. Validation Contract

The authorized implementation must run and record:

1. `git diff --check`;
2. exact changed-file comparison against Section 3;
3. prohibited-path check for `backend/` and all non-authorized files;
4. reference existence checks for every new repository path;
5. terminology search proving canonical labels are consistent;
6. search proving QG-0 through QG-12 still exist and were not renumbered;
7. search proving all eleven Manifesto principles remain present and unchanged;
8. manual hierarchy and Human-authority review;
9. manual prospective-adoption and completed-PATCH compatibility review;
10. independent Final Review.

No backend test suite is required because executable files are prohibited.

## 8. Rollback Contract

Rollback removes or reverses only the exact PATCH-028.0 section insertions and
the PATCH-028.0 registry row. It must preserve all pre-existing user-owned
Foundation v1.2/Manifesto edits and unrelated worktree changes. No broad file
replacement, checkout, reset, or history rewrite is permitted.

Before implementation, the plan must capture the current diff of every
overlapping file so rollback can distinguish earlier changes from PATCH-028.0.

## 9. Stop Conditions

Stop and return to governance if:

- registry or Human acceptance is absent;
- an exact edit requires a file outside Section 3;
- current content contradicts EDS assumptions;
- preserving existing user changes cannot be guaranteed;
- QG-M1 would change Foundation meaning or existing gate semantics;
- terminology cannot be made cross-consistent within the authorized files;
- any backend or executable change appears necessary.
